# 다음 세션 핸드오프 — Market Studio

## 목표

나무 PLUG 데이터를 이용하는 Market Studio를 계속 개발한다. 가장 최근 미완료 요청은 코스피·코스닥·S&P 500 지수의 나무 PLUG 코드를 찾아 실제 응답을 검증하고 대시보드에 연결하는 것이다.

## 현재 상태

- `server.mjs`, `app.js`, `index.html`, `master.json`으로 구성된 로컬 전용 프로토타입이다. 매매 API는 구현하지 않았다.
- 국내 종목 시세·일봉, 4,332개 종목의 순차 히트맵, `.DJI` 다우 지수, AAPL 시세 응답의 환율 필드는 구현됐다. 2026-11-21 히트맵 4,332/4,332 성공을 브라우저에서 한 번 확인했다. 이 결과는 저장되지 않는다.
- `.KS11`, `.KQ11`, `.SPX`는 기존 후보일 뿐이며 실제 서버 응답을 검증하지 못해 실패 표시된다. 성공한 지수로 취급하지 않는다. 나무 공식 테스트베드의 해외 지수 예시는 `.DJI`다.
- 전체 조회는 종목별 REST 호출을 공유 큐에서 350ms 이상 간격으로 실행한다. 약 25분 이상 걸릴 수 있고 탭이 닫히거나 새로고침되면 진행 상황을 잃는다. 실패·수신 시각이 종목마다 다르다.
- `master.json`은 2026-11-21 정적 스냅샷으로 자동 갱신되지 않는다. 공식 원본 `m_new_stock.mst`는 CP949, 237바이트 고정 레코드다. ETF·ETN은 `etfCurrent`, 주식은 `currentPrice`를 사용한다.
- Market Studio는 DB/D1을 사용하지 않는다. 별도 `stock-trading/data/trading.db`와 `stock-trading/wrangler.toml`의 `sarah-ai-db`는 다른 프로젝트이고 자동 동기화되지 않으며, 2026-11-22 확인 시 원격 D1에 0003_kiwoom_market_data.sql이 미적용이었고 stocks와 price_history가 각각 0행이었다. 메인 프로젝트의 `buldang-parking-db`는 주차장용이다.
- 확인 당시 상위 Git 저장소에서 `market-studio/`와 `stock-trading/` 모두 추적되지 않았다. Git remote가 있다고 해서 집 PC에 이 파일들이 있다고 가정하지 말 것.

## 이어서 할 일

1. 집 PC의 실제 체크아웃과 파일·Git 상태, Node.js, 나무 PLUG 신청 상태부터 확인한다. README와 실제 동작이 다르면 코드와 실제 응답을 우선하고 문서를 고친다.
2. 나무 공식 명세, 테스트베드, 종목마스터의 코드표에서 세 지수 코드를 확인한다. `symbolIndexFxPeriod`는 해외 지수·환율용이므로 국내 지수 지원을 단정하지 않는다. 후보를 쓰더라도 응답의 종목명·코드·값·시각과 실제 지수 정체를 검증한 뒤 연결한다. 부정확한 값은 숨기고 이유를 표시한다.
3. 기존 `marketIndex()`는 응답 `iem_cd`가 요청과 정확히 같아야 성공한다. 기존 후보 실패가 잘못된 코드 때문인지 API 자체 오류인지, 반환 코드 정규화·응답 필드·지연·권한 제한 때문인지 구분한다. 인증값·토큰·계좌정보를 로그에 출력하지 않는다.
4. 히트맵 수집을 장시간 안정적으로 유지하는 방안을 검토한다. 중단 후 재개, 수신 시각·오류, 오래된 마스터 갱신, 전체 데이터 완료 여부를 명확히 한다. DB/D1 도입은 사용자 목표와 배포 환경을 먼저 확인하고 마이그레이션·접근 제어를 설계한다.
5. 실제 API와 브라우저에서 지수·환율·히트맵 성공/실패, 모바일 화면을 검증하고 README를 갱신한다. 실제 검증하지 않은 것은 미완료로 보고한다.

## 보안과 운영

- 앱키·앱시크릿·토큰을 채팅, Git, 스크린샷, 명령 출력에 남기지 않는다. 사용자에게 새 발급·약관 동의가 필요하면 명시적으로 설명하고 사용자가 직접 처리한다.
- 시세만 읽는다. 주문·계좌 조회 등은 별도 요청 없이 수행하지 않는다. 나무 REST 공식 한도는 초당 최대 5건이므로 토큰을 불필요하게 재발급하거나 과도한 조회를 하지 않는다.
- 로컬 서버는 `127.0.0.1:8766`만 사용하며 실행 중 메모리에 키와 토큰을 유지한다. 상태 확인만으로 원격 D1의 배포나 최신화를 주장하지 않는다.
